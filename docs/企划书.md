# 企业智能体平台企划书（当前单机 MVP）

> 本文描述仓库当前已经形成的技术与功能框架。未实现的多机调度、对象存储、动态
> MCP、常驻 Pi 进程和生产级身份系统不写成现有能力。

## 一、建设目标

当前阶段的目标是在一台具备 KVM 的 Linux Host 上，为每名用户提供一套可认证、
可持续对话、可持久化文件、可暂停恢复且与其他用户隔离的 Agent 运行环境。

平台采用 Firecracker microVM 作为隔离执行单元，Pi Agent 作为当前核心 Agent。
上层通过 Control Plane HTTP API 使用平台，不直接控制 Firecracker，也不直接连接
Guest 中的 Pi RPC。

当前约束如下：

- 每名用户最多拥有一个受管实例，并且最多运行一个实例；
- 每名用户绑定一块稳定的 ext4 数据盘；
- 用户可以在数据盘内创建多个 Workspace，每个 Workspace 可以拥有多个 Conversation；
- 一个实例同一时刻串行执行 Agent 任务；
- Control Plane 只监听 Linux Host 的 `127.0.0.1:18090`；
- Pi 仍按 TCP 连接启动，尚未改造成 Guest 内常驻进程；
- MCP、动态 Skill、向量知识库和多服务器调度不属于当前实现。

## 二、总体架构

```text
macOS / Windows / 上层应用
        │ HTTP + SSE（经 SSH 隧道或同源代理）
        ▼
Control Plane（Ubuntu Host，127.0.0.1:18090）
        ├── AuthStore：用户、密码派生值、登录会话
        ├── WorkspaceStore：Workspace 与当前选择
        ├── TaskStore：Conversation、消息缓存、Task、Event
        ├── InstanceStore：产品层实例状态与属主关系
        ├── AgentRuntimeAdapter：统一 Agent 运行时接口
        │       └── PiRuntimeAdapter
        │               └── Pi Gateway：Pi RPC JSONL 协议适配
        └── InstanceRuntime：microVM 创建、暂停、恢复、停止和销毁
                    │
                    ├── NetworkManager：SQLite 网络租约、TAP、nftables
                    ├── Tool Gateway：模型凭据外置和流式转发
                    └── Jailer + Firecracker + KVM
                                │ TCP 8080 / JSONL
                                ▼
                         Guest socat
                                │ stdin/stdout
                                ▼
                         Pi --mode rpc
```

系统分为三类边界：

1. **业务控制边界**：Control Plane 校验身份、所有权、配额和状态迁移；
2. **运行隔离边界**：Jailer、Firecracker、KVM 和独立 Guest Linux 隔离 Agent；
3. **凭据边界**：真实 DeepSeek API Key 只保留在 Host，Guest 只访问 Tool Gateway。

## 三、核心业务对象

### 3.1 User

User 是平台登录主体。当前使用本地账号、PBKDF2-SHA256 密码派生和 12 小时
HttpOnly Cookie 会话。数据库只保存登录令牌的 SHA-256 摘要，不保存明文密码或
明文会话令牌。

### 3.2 Instance

Instance 是平台登记的一套用户运行资源，不等同于一个永久运行的 Firecracker
进程。实例停止后，Firecracker、TAP、nftables 和 Jailer 临时目录会被清理，实例
记录及用户数据盘继续保留。再次启动时重新创建计算资源并挂载同一用户数据盘。

### 3.3 Workspace

Workspace 是用户数据盘内的文件工作目录。平台数据库保存 Workspace 的 ID、名称、
目录名和当前选择；实际文件位于数据盘的：

```text
/workspace/workspaces/<workspace-id>
```

### 3.4 Conversation 与原生 Session

Conversation 是平台展示和权限控制使用的会话对象。Pi 原生 Session JSONL 位于用户
数据盘的 `pi-state/agent/sessions/`，是恢复 Pi 上下文的权威数据。

SQLite `messages` 表保存面向 CLI 和未来前端的历史消息缓存。打开旧会话时优先读取
SQLite，不再为展示历史而冷启动 Pi；缓存缺失时才通过 Agent Runtime Adapter 读取
Pi 原生 Session 并回填缓存。

### 3.5 Task 与 Event

Task 表示一次用户消息触发的 Agent 执行。Task 状态为 `queued`、`running`、
`completed` 或 `failed`。执行过程追加统一平台事件，并通过 SSE 推给客户端：

- `run.started`；
- `message.delta`；
- `tool.started`；
- `tool.completed`；
- `run.completed`；
- `run.failed`。

Pi 的 `message_update`、`tool_execution_start`、`agent_settled` 等原生字段只存在于
Pi Gateway 内部，不进入 Control Plane 的通用业务语义。

## 四、Agent Runtime 边界

Control Plane 通过 `AgentRuntimeAdapter` 调用核心 Agent，而不是直接依赖 Pi RPC。
当前实现是 `PiRuntimeAdapter`，它包装 Pi Gateway 的执行和历史读取能力，并把 Pi
异常转换为统一的 `AgentRuntimeError`。

```text
Control Plane
    │ execute / get_messages
    ▼
AgentRuntimeAdapter
    ▼
PiRuntimeAdapter
    ▼
PiGateway
    ▼
Guest Pi RPC
```

这层抽象已经建立，但当前并未实现运行时动态切换。若开发阶段更换核心 Agent，主要
替换 Adapter、Guest 启动协议、rootfs 中的 Agent 软件和原生 Session 映射；用户、
Workspace、Conversation、Task、SQLite、Firecracker 和网络管理可以继续复用。

## 五、Pi RPC 当前运行方式

Guest 启动后，`agent-init.sh` 使用 socat 在 Guest IP 的 `8080` 端口监听。Host 的
Pi Gateway 每次发起任务或回源读取历史时建立 TCP 连接，socat 为该连接执行
`pi-rpc-session.sh`，脚本再启动一个 `pi --mode rpc` 进程。

首条 JSONL 中的平台扩展字段由 Guest 包装脚本处理：

- `workspace` 决定 Pi 的当前工作目录；
- `session` 映射为 Pi 的 `--session` 或 `--session-id`；
- 处理后的原生 Pi 命令通过 stdin 发送，Pi 的 stdout 通过同一 TCP 连接返回。

连接关闭后 Pi 进程退出，因此当前实现不是常驻 Pi。SQLite 消息缓存已经解决“打开
旧会话必须重新启动 Pi”的主要等待，但每次真实 Agent 执行仍会启动 Pi 进程。

## 六、microVM 与持久化

### 6.1 共享系统资产

- Guest 内核：`/srv/fc/artifacts/vmlinux-<version>`；
- 只读系统盘：`/srv/fc/artifacts/agent-rootfs.ext4`；
- Build ID：`/srv/fc/artifacts/agent-rootfs.build-id`；
- Manifest：`/srv/fc/artifacts/agent-rootfs.manifest`。

rootfs 当前包含 Ubuntu 24.04 用户态、Node.js 22.19.0、Pi Agent 1.0.0、socat、
Guest 初始化脚本和非 root `pi` 用户。

### 6.2 用户数据盘

用户与数据盘的稳定绑定保存在 SQLite。数据盘文件位于：

```text
/srv/fc/volumes/users/<user-id>.ext4
```

数据盘内部主要包含：

```text
workspace/
└── workspaces/<workspace-id>/

pi-state/
└── agent/sessions/
```

Guest 启动时将 `/dev/vdb` 挂载到 `/mnt/agent-data`，然后执行：

```text
/mnt/agent-data/workspace → /workspace
/mnt/agent-data/pi-state → /home/pi/.pi
```

因此 Workspace 文件和 Pi 原生 Session 都直接写入持久化数据盘。

## 七、实例创建与生命周期

实例启动流程为：

1. Control Plane 校验用户所有权、单实例配额和状态；
2. InstanceRuntime 查找或创建用户数据盘；
3. NetworkManager 从 `172.29.0.0/16` 中分配一个 `/30` 网络槽位；
4. 创建 TAP、Host IP、路由及实例独立 nftables 规则；
5. 启动 Host Tool Gateway，并准备只含占位凭据的 Guest 配置；
6. 将内核、rootfs和数据盘硬链接进Jailer chroot，并在其中生成`config.json`；
7. Jailer 以低权限用户启动 Firecracker；
8. Guest 挂载数据盘、配置网络并启动 Pi RPC 监听；
9. Host 看到 `AGENT_RUNTIME_READY` 和 `PI_RPC_READY` 后登记运行元数据；
10. 独立空闲回收进程按照 300 秒阈值管理实例。

支持的状态包括：`created`、`starting`、`running`、`stopping`、`stopped`、
`suspending`、`suspended`、`resuming` 和 `failed`。

暂停时 Firecracker 生成 `memory.snap` 与 `vmstate.snap`，并保存与 rootfs Build ID、
用户数据盘、网络槽位相关的 manifest。恢复时验证这些配对信息，重新创建 Host 网络、
Jailer 和 Tool Gateway，再加载快照。快照不替代用户数据盘。

## 八、网络与凭据

每个实例占用一个 `/30` 子网，其中一个地址属于 Host TAP 网关，一个地址属于 Guest。
租约保存在统一的 `/var/lib/fc/control-plane.db` 中。旧 JSON 租约存储只用于兼容历史
实例清理，新受管实例统一使用 SQLite。

nftables 规则允许 Guest 访问必要的 Host Gateway 和受控外网，同时阻止访问其他私网
及其他实例。DeepSeek API Key 保存于 Linux Host 用户目录，运行时复制到仅 Host
sidecar 可读的临时凭据文件；Guest 只能使用占位令牌访问 Tool Gateway。

## 九、数据库边界

当前统一数据库为：

```text
/var/lib/fc/control-plane.db
```

其中保存：

- 用户与登录会话；
- 实例、属主和产品状态；
- Runtime 进程元数据及 sidecar PID；
- 用户数据盘绑定；
- 网络租约；
- Workspace 与当前选择；
- Conversation 元数据；
- 消息读取缓存；
- Task 与统一事件。

数据库不保存 Guest 文件、Pi 原生 Session 文件、模型 API Key、rootfs 或快照正文。

## 十、当前交付能力与边界

当前已实现：

- KVM、Firecracker、Jailer 和 ARM64/x86_64 构建资产；
- 只读共享 rootfs 与用户持久化数据盘；
- 用户认证、属主隔离和单用户单实例配额；
- Workspace、Conversation、Task 和 SSE 流式事件；
- AgentRuntimeAdapter 与 PiRuntimeAdapter；
- Pi RPC、DeepSeek模型调用和 Host凭据隔离；
- SQLite网络租约、运行元数据和消息缓存；
- 空闲回收、异常恢复、暂停和快照恢复；
- macOS本地`agentctl`终端客户端及端到端验收脚本。

当前未实现：

- Guest内常驻Pi进程；
- 动态切换多个Agent Runtime；
- MCP Gateway和动态MCP接入；
- 动态Skill授权与热加载；
- 向量数据库和企业知识库；
- 多Host调度、对象存储数据卷同步和生产级高可用；
- 仓库内正式Web前端。
