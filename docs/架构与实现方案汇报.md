# 企业智能体平台：架构与当前实现汇报

> 版本边界：本文只描述当前仓库已经实现并经过代码或脚本验证的能力。Pi常驻进程、
> 多Agent动态切换、MCP、动态Skill、知识库和多服务器调度不写成现状。

## 一、一页摘要

本项目已经形成一个可运行的单机企业Agent平台原型。平台在Linux Host上使用KVM、
Firecracker和Jailer创建隔离microVM；当前核心Agent为Pi Agent，通过TCP + JSONL RPC
与Host通信；真实模型凭据由Host Tool Gateway保管，不进入Guest。

平台已经具备本地用户认证、单用户单实例、稳定用户数据盘、多个Workspace、多个
Conversation、任务流式事件、SQLite消息缓存、空闲回收、异常恢复和Firecracker快照
暂停/恢复。macOS上的`agentctl`是当前验收客户端，未来上层后端或前端复用同一套
HTTP + SSE API。

## 二、当前系统分层

| 层级 | 当前组件 | 主要职责 |
|---|---|---|
| 客户端 | `agentctl`、未来上层应用 | 登录、选择Workspace/会话、发消息、消费SSE |
| 控制面 | `services/control-plane/server.py` | API、认证、所有权、状态机、任务与会话编排 |
| Agent抽象 | `services/agent-runtime/agent_runtime.py` | 隔离平台语义与具体Agent协议 |
| Pi协议适配 | `services/pi-gateway/gateway.py` | TCP/JSONL、Pi事件解析、统一事件转换 |
| 实例编排 | `services/instance-manager/runtime.py` | microVM、数据盘、网络、sidecar、快照 |
| 生命周期 | `lifecycle.py`、`runtime_store.py` | PID校验、空闲回收、运行元数据和清理 |
| 网络 | `network_manager.py` | SQLite租约、/30地址池、TAP、nftables |
| 模型网关 | `services/tool-gateway/gateway.py` | DeepSeek凭据注入、流式转发、脱敏审计 |
| Guest | `agent-init.sh`、`pi-rpc-session.sh` | 挂盘、网络、Pi RPC入口和非root执行 |
| 虚拟化 | Jailer、Firecracker、KVM | 进程约束、VMM和硬件虚拟化 |

## 三、控制面与数据库

Control Plane是平台业务入口，只监听`127.0.0.1:18090`。它接收HTTP请求、校验
HttpOnly Cookie、限制资源归属与配额，并调用InstanceRuntime和AgentRuntimeAdapter。

统一SQLite数据库位于`/var/lib/fc/control-plane.db`，使用WAL模式，包含：

- `users`与`auth_sessions`；
- `instances`；
- `runtime_instances`与`runtime_sidecars`；
- 用户数据盘绑定；
- 网络租约；
- `workspaces`与当前Workspace偏好；
- `conversations`与`messages`；
- `tasks`与`task_events`。

旧`/var/lib/fc/tasks/tasks.db`仅作为一次性迁移来源。正式新数据统一写入
`control-plane.db`。旧JSON网络租约和JSON运行元数据也只用于兼容迁移。

## 四、用户、实例、Workspace与会话

### 4.1 用户与实例

当前每名用户最多创建一个实例，并且最多运行一个实例。实例是业务资源记录，运行中
才对应真实Firecracker进程。停止实例不会丢失Workspace文件和Pi Session。

### 4.2 用户数据盘

每名用户稳定绑定一块1 GiB ext4数据盘：

```text
/srv/fc/volumes/users/<user-id>.ext4
```

实例ID可以变化，但用户数据盘绑定保持稳定。数据盘由Host创建、检查和离线维护，
运行时作为`/dev/vdb`提供给Guest。

### 4.3 Workspace

Workspace是同一用户数据盘内的目录隔离：

```text
/workspace/workspaces/<workspace-id>
```

数据库保存Workspace名称、目录名和当前选择。删除Workspace前会检查进行中任务，
停止计算资源后离线挂载数据盘并删除对应目录。

### 4.4 Conversation与Session

Conversation是平台对象；Pi Session是当前Agent的原生上下文文件。两者通过
`pi_session_id`关联。Pi原生Session JSONL位于持久化数据盘，是上下文恢复的权威来源。

SQLite `messages`表是面向客户端的读取缓存：

```text
打开旧会话
  ├─ SQLite已有消息 → 直接分页返回
  └─ 缓存缺失 → 启动必要运行资源 → Pi读取原生Session → 回填SQLite
```

因此正常打开旧会话不再触发Pi冷启动，同时真实执行仍使用Pi原生Session保持上下文。

## 五、Agent Runtime与Pi通信

### 5.1 统一抽象

Control Plane依赖`AgentRuntimeAdapter`的`execute()`和`get_messages()`，不直接调用
Pi Gateway。当前`PiRuntimeAdapter`把PiGateway异常映射为统一Runtime错误。

这不是多Agent动态切换系统，而是一个最小解耦边界。未来开发阶段更换核心Agent时，
可以替换Adapter和Guest运行时，而不重写用户、会话、任务、SQLite和microVM管理。

### 5.2 当前Pi进程模型

Guest的socat监听`8080`。每条Host TCP连接会执行一次`pi-rpc-session.sh`，再启动一个
新的`pi --mode rpc`进程。脚本根据首条记录中的Workspace与Session选择工作目录和
原生Session，然后移除平台扩展字段，将剩余JSONL交给Pi。

Pi的stdout通过TCP返回Host；stderr进入Guest串口日志。连接结束后Pi刷盘并退出，
socat重新监听。因此当前不是常驻Pi，也没有Guest Supervisor。

### 5.3 统一事件

Pi Gateway将原生事件转换为平台事件：

| Pi原生含义 | 平台事件 |
|---|---|
| Agent开始执行 | `run.started`或进度事件 |
| 文本增量 | `message.delta` |
| 工具开始 | `tool.started` |
| 工具结束 | `tool.completed` |
| Agent稳定完成 | `run.completed` |
| 传输或运行失败 | `run.failed` |

Control Plane、SQLite、SSE和CLI只依赖平台事件，不解析Pi原生字段。

## 六、模型调用与凭据边界

Pi的数据请求链路为：

```text
Pi（Guest）
  → http://<Host TAP IP>:18082/v1
  → Tool Gateway
  → 注入Host上的DeepSeek API Key
  → DeepSeek
  → 流式响应原路返回Pi
```

Guest只持有占位凭据。真实Key来自Host用户目录，在实例启动时复制成权限受限的临时
sidecar文件。审计日志不记录Authorization正文。nftables阻止Guest绕过网关直接访问
受限私网，模型调用由Host侧治理。

## 七、microVM启动流程

1. 校验用户、实例配额和状态；
2. 查找或创建用户数据盘，执行`e2fsck`；
3. 从SQLite网络租约表预留`/30`槽位；
4. 创建TAP、路由和nftables；
5. 写入Pi provider占位配置并启动Tool Gateway；
6. 把内核、rootfs和数据盘硬链接进Jailer chroot；
7. 生成Firecracker `config.json`；
8. Jailer以低权限UID/GID、cgroup v2和`nofile=2048`启动Firecracker；
9. Guest挂载数据盘并配置网络；
10. Guest启动socat监听并输出READY标记；
11. Host登记Runtime PID、sidecar PID、网络和数据盘元数据；
12. 启动独立空闲回收watcher。

当前冷启动约5秒，主要耗时是Guest内核启动。Node/Pi版本校验与静态权限检查已前移
到rootfs构建阶段，Host就绪轮询已缩短。

## 八、磁盘与文件系统

### 8.1 rootfs

`agent-rootfs.ext4`是全平台共享的4 GiB只读系统盘，包含Ubuntu Noble用户态、
Node.js 22.19.0、Pi Agent 1.0.0、socat和Guest脚本。Build ID用于判断系统盘内容及
快照兼容性。

### 8.2 数据盘挂载

Guest内核将rootfs作为`/dev/vda`根设备，将用户数据盘识别为`/dev/vdb`。初始化脚本
把`/dev/vdb`挂载到`/mnt/agent-data`，再执行两个bind mount：

```text
/mnt/agent-data/workspace → /workspace
/mnt/agent-data/pi-state → /home/pi/.pi
```

写入`/workspace`或`/home/pi/.pi`最终修改的是Host用户数据盘中的ext4数据块，不需要
关机时再执行一次“复制保存”。停止前的sync用于把页缓存及时刷盘。

## 九、网络管理

NetworkManager由五部分组成：LeaseStore接口、SQLiteLeaseStore、地址池计算、
LinuxNetworkDriver和编排器。新实例统一使用SQLite租约。

每个实例分配一个`/30`子网、Host TAP IP、Guest IP、TAP名称和nftables表名。创建
失败时按反向顺序回滚Linux资源；清理不完整时租约进入error，避免槽位被错误复用。

## 十、生命周期与恢复

### 10.1 空闲回收

默认空闲阈值为300秒。有效用户任务和心跳刷新活动时间；空队列轮询、状态查询和
TCP保活不算用户活动。实例繁忙时回收器跳过，任务结束后重新计算空闲时间。

### 10.2 控制面重启与进程异常

Runtime元数据保存在SQLite，并记录PID及`/proc`进程启动ticks，避免PID复用误判。
Control Plane重启后可重新对账；Firecracker异常退出后，平台将业务状态修正为失败，
清理网络和临时资源，并保留用户数据盘供再次启动。

### 10.3 手动暂停与恢复

暂停生成`memory.snap`、`vmstate.snap`和`manifest.json`。恢复前校验属主、rootfs
Build ID、数据盘路径和原网络槽位，再重新创建Host资源并加载Firecracker快照。

快照保存内存与虚拟设备状态，不包含数据盘正文，也不等同于Conversation历史缓存。

## 十一、API与客户端

Control Plane提供：

- 登录、登出和当前会话；
- Workspace创建、选择、删除和列表；
- Conversation创建、删除、历史分页；
- 发送消息、Task查询、事件查询与SSE；
- 实例创建、启动、状态、停止、暂停、恢复和销毁。

`agentctl`运行在macOS本机，通过SSH隧道访问Control Plane。它不直接执行Firecracker、
不读取SQLite，也不直接连接Guest Pi RPC。正式前端可复用相同HTTP + SSE契约。

仓库提供分层smoke test，覆盖：

- KVM、Firecracker与最小Guest启动；
- rootfs、非root Pi用户和静态权限；
- Jailer、只读系统盘和持久化数据盘；
- TAP、nftables、受控出站和模型网关；
- 网络租约申请与释放；
- 生命周期、空闲回收与数据保留；

- Pi真实模型调用、原生Session重启续聊和SQLite缓存；
- Control Plane重启、Firecracker崩溃恢复；
- Firecracker快照创建与恢复；
- `agentctl`完整端到端流程。

## 十三、当前边界

当前不具备：

- Guest内常驻Pi进程；
- 多Agent运行时动态切换；
- MCP Gateway、动态MCP与动态Skill；
- 向量数据库和知识库检索；
- 多服务器调度和对象存储数据卷同步；
- 生产级OIDC、企业权限体系、TLS入口和正式Web前端。

这些内容不应在当前演示或接口说明中被描述为已经完成。
