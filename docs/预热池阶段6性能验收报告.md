# 预热池阶段 6 性能验收报告

## 1. 验收目的

本报告验证同一 Ubuntu Host 上，用户通过 localhost Control Plane 启动逻辑实例时，
预热命中相对完整冷启动的平台侧耗时改善，并记录空闲预热机的基础资源成本。结论不包含
用户到服务器的公网延迟，也不等价于多用户并发压力结果。

## 2. 样本与口径

- 正式主指标：2026-11-18 完成冷启动 30 次、预热启动 30 次；
- 资源与里程碑采集：新版脚本完成冷启动 3 次、预热启动 3 次，另有冷/热各 5 次不计入结果的热身；
- 主指标：`clientObservedMs`，即 localhost 发出 `POST /start` 到收到成功响应；
- 平台内部对照：`startupOperationTiming.totalMs`；
- Guest 诊断里程碑：`guestDeclaredRpcReadyMs`；
- P95 采用 `ceil(0.95 × N)` 所在样本，不删除慢样本。

## 3. 正式性能结果

| 指标 | 冷启动 | 预热启动 | 结论 |
|---|---:|---:|---|
| `clientObservedMs P95` | 6188 ms | 1195 ms | 降低约 80.7% |
| 成功样本 | 30 | 30 | 全部完成 |
| STOP 竞态 | 0 | 0 | 未再复现 |

阶段 6.3 的通过门槛为预热 P95 不高于冷启动 P95 的 60%。实测预热仅为冷启动的约
19.3%，因此主性能门槛通过。

## 4. 新版里程碑与统计验证

| 指标 | 冷启动 | 预热启动 |
|---|---:|---:|
| `clientObservedMs P50` | 5986 ms | 956 ms |
| `clientObservedMs P95` | 5990 ms | 974 ms |
| `totalMs P50` | 5978 ms | 941 ms |
| `totalMs P95` | 5984 ms | 965 ms |
| `guestDeclaredRpcReadyMs P50` | 5917 ms | 880 ms |
| `guestDeclaredRpcReadyMs P95` | 5924 ms | 897 ms |
| 成功率 | 100% | 100% |

新版样本的平台侧 P95 降幅为 83.74%，实际策略回退率为 0。自动 `verdict` 的样本数、
成功率、策略、40% 性能门槛和 Guest 里程碑检查全部为 `true`。

## 5. 空闲预热资源成本

| 指标 | 结果 |
|---|---:|
| 空闲 Firecracker VMM RSS 均值 | 66499 KiB |
| 空闲 Firecracker VMM PSS 均值 | 66487 KiB（约 64.9 MiB） |
| 后台补出一台 ready 的平均等待 | 5510 ms |
| 补池等待 P95 | 6511 ms |
| 每台预热机活动网络租约 | 1 个 `/30` 槽位 |
| `MemAvailable` 差值估算 | 26519 KiB |

`MemAvailable` 差值只有 1 个池空基线样本，且会受 Linux 页缓存与后台进程波动影响，因此
26 MiB 仅用于辅助观察。当前容量规划应优先使用空闲 VMM PSS 约 65 MiB，并额外保留
Guest 内存、Host 页缓存及 Worker/Control Plane 安全余量。

## 6. 正确性与边界

- 冷启动与预热启动成功率均为 100%，预热策略回退率为 0；
- 每轮停止后检查 binding、attachment、租约、Jailer 和占位盘，未发现遗留；
- 之前的 STOP 409 竞态已通过过渡状态保护和 monitor 实例锁修复，30+30 验收未再复现；
- 本测试是单实例、顺序执行的性能基准，不是多用户并发压力测试；
- 资源成本为 3 个新版样本的初步值，部署容量不应只根据该小样本直接扩大预热池。

## 7. 阶段结论

阶段 6.2 与 6.3 通过。预热池已证明能显著降低单实例平台侧启动耗时，且基础资源成本
已可观测。预热功能继续默认关闭；下一步先执行多用户并发领取与池空回退验收，不直接执行生产灰度。
